Slide 1: Expense Tracker | 0:00-1:00
Speaker: Prateek Sahay
Hi, I am Prateek Sahay, and my teammate is Venkata Sai Makani. Our project is an expense tracker written in two languages: Python and C++. The app helps someone record purchases and understand where their money goes. We kept the features the same in both versions so we could compare how the languages handle the same problem. It runs in a terminal, where the user types a command and sees a result. Today we will explain the features, show both versions, look at one small code example, and share what we learned. I will cover the first half, and Venkata will cover the second half.

Slide 2: What can the app do? | 1:00-2:00
Speaker: Prateek Sahay
The app has four main features. First, we can add an expense with a date, an amount, a category, and a short description. Second, we can view all saved expenses or search for a word in the category or description. Third, we can narrow the list to a date range or a category, such as Food. Finally, we can calculate spending for each category and the total for all expenses. We also added a delete option so a user can remove an entry by its ID. The data is saved, so closing and reopening the app does not lose the records. Both languages support these same features.

Slide 3: A simple example | 2:00-3:00
Speaker: Prateek Sahay
Imagine buying lunch on October 2 for 12 dollars and 34 cents. We enter the date, choose Food as the category, and use Lunch, campus as the description. The app creates an ID so we can refer to that entry later. If we want to review only food spending, we filter by Food. If we want to find campus purchases, we search for campus. We can also limit the results to a date range. Then the summary adds the matching amounts. The steps are identical in Python and C++, which makes it easy to compare the results without learning two different sets of commands.

Slide 4: How are expenses saved? | 3:00-4:00
Speaker: Prateek Sahay
We save the expenses in a CSV file. CSV is a simple text format with columns separated by commas. Each row contains an ID, date, amount, category, and description. Both versions use the same columns, so Python can read a file saved by C++, and C++ can read a file saved by Python. We store money as whole cents: 12 dollars and 34 cents becomes 1,234 cents. That keeps the calculations exact instead of relying on decimal approximations. Before saving, the app checks the input. It also writes a replacement file before replacing the original, which helps protect the existing records if saving fails.

Slide 7: One clear code difference | 6:00-7:00
Speaker: Venkata Sai Makani
These small examples come directly from our source files. Both name the same five fields: ID, date, amount in cents, category, and description. In Python, an expense is a dictionary, which means values are stored under named labels. TypedDict describes the expected values for those labels. Those hints do not automatically check user input, so our validation functions do that work. In C++, a struct groups the fields into a record, and each field has a declared type, such as a number or text. The compiler checks the declared field types when building the program. C++ still needs input validation. Different code styles represent the same expense.

Slide 8: What felt different? | 7:00-8:00
Speaker: Venkata Sai Makani
For this project, Python was convenient for making quick changes and running them immediately. Its built-in date and CSV tools reduced the amount of code we needed to write. C++ needed a build step, and we wrote more code for date checks and reading CSV files. Its explicit field types made the record structure clear and helped catch type mistakes during compilation. Python uses separate functions for operations such as adding and filtering. C++ groups related operations inside a Tracker class. A class is simply a way to keep related data and operations together. Both approaches worked. These are observations about our implementations, not measurements of which language runs faster.

Slide 9: How did we check it? | 8:00-9:00
Speaker: Venkata Sai Makani
We used automated checks to confirm that the apps work as expected. Our recorded verification run passed 62 tests: 7 focused Python checks and 55 checks for behavior and file sharing across the two versions. We checked exact totals, date ranges, category filters, search, adding and deleting records, and reopening saved files. We also tried bad input, such as an impossible date or an amount with too many decimal places. The app should report a clear error and preserve the valid data. Finally, we checked that each program can read files written by the other. Matching a screenshot once is helpful, but checking many cases gives us more confidence.

Slide 10: What we learned | 9:00-10:00
Speaker: Venkata Sai Makani
The main lesson is that we can solve the same problem in different ways. Python helped us move quickly with built-in tools and simple functions. C++ encouraged us to define the record structure clearly and build the program before running it. In both versions, good input checks, exact money calculations, and clear organization mattered. Keeping the features and storage format the same made the comparison useful because we could focus on the code choices. The GitHub repository contains the source, sample data, tests, and instructions for running both programs. Thank you for listening. We are happy to answer questions or show one of the commands again.

Slide 7: Types and containers shape the implementation (7:20-8:30)
Speaker: Prateek Sahay
- Python records are dictionaries; TypedDict documents their expected shape
- Python type hints do not enforce field types at runtime
- C++ Expense fields have compiler-enforced types and value ownership
- Lists/dictionaries versus std::vector/std::map/std::set

Prateek, 7:20-8:30. Navigate to the Expense declarations shown on the slide. In Python, expense['amount_cents'] looks up a string key in a dictionary. TypedDict helps readers and optional type-checking tools; runtime validation in parse_amount, parse_date, and clean_text remains essential. Python dates are date objects, whereas C++ stores a validated string. C++ accesses expense.amount_cents and the compiler knows its fixed-width integer type. Both still need input checks: static typing does not make an invalid date valid or prevent arithmetic overflow automatically. Explain that Python stores records in a list; C++ stores Expense values in a vector, with a map for sorted category totals and a set to detect duplicate stored IDs. Handoff: Venkata will show how those records are filtered.

Slide 8: Filtering: comprehension versus explicit control flow (8:30-9:40)
Speaker: Venkata Sai Makani
- Python expresses selection with a list comprehension and predicate conditions
- C++ uses a loop, std::optional bounds, and continue for rejected records
- Both apply inclusive dates and the same exact category condition
- Python returns references to dictionaries; C++ copies selected Expense values

Venkata, 8:30-9:40. Read the Python predicate as a description of eligible records: absent bounds allow all dates; supplied bounds must match. Explain short-circuit evaluation and that this expression does not mutate the input list. In cpp/tracker.cpp, continue rejects an expense before the later search and selected.push_back steps. std::optional represents an absent filter explicitly. Fixed-width, validated date strings make lexicographic comparisons valid; Python directly compares date objects. Point to lowercase_ascii in C++ and lower() in Python; because the accepted text is ASCII, they implement the same search behavior. Clarify the ownership tradeoff: the Python result is a new list referencing existing dictionaries, while the C++ result contains copies of matching values. Handoff: Prateek will compare category aggregation and exact totals.

Slide 9: Aggregation and checked integer totals (9:40-10:45)
Speaker: Prateek Sahay
- Python dict.get supplies a default when a category is first encountered
- C++ std::map indexes a category and updates its integer total
- Python sorts categories when printing; C++ map iteration is already sorted
- Both check the shared signed 64-bit total bound and format integer cents

Prateek, 9:40-10:45. Explain the Python get(category, 0) pattern and the tuple containing category totals and the overall amount. In C++, auto& binds a reference to the stored map value, and operator[] creates a zero-initialized integer for a missing category. Explain that Python's arbitrary-precision int does not normally overflow at the C++ boundary, but we deliberately impose the same total limit through checked_total. C++ checked_add protects fixed-width addition. Point to format_amount and format_money: both divide by 100 for dollars and take a remainder for cents. Revisit the demonstrated $0.30 result as correctness evidence, not a speed comparison. Handoff: Venkata will show how files and temporary resources are managed.

Slide 10: Resource ownership: context managers and RAII (10:45-11:55)
Speaker: Venkata Sai Makani
- Python with closes files; try/finally removes temporary files
- C++ streams and a temporary-file destructor release resources on scope exit
- std::vector and std::string own allocations without manual new/delete
- Successful writes replace the target; atomic replacement is not writer locking

Venkata, 10:45-11:55. Define RAII in plain language: a C++ object's lifetime controls a resource's lifetime. Streams close when they leave scope, and the TemporaryFile destructor removes an uncommitted file even during exception unwinding. Point out deleted copy operations on TemporaryFile to prevent two objects from owning the same cleanup. Contrast Python with blocks and its finally cleanup in save_expenses. The C++ vector owns record values, so there are no owning raw pointers and no new/delete calls. Open replace_file: Windows uses MoveFileExW with replacement flags; POSIX uses filesystem rename. Python uses os.replace. Same-directory temporary writes protect against partial replacement after a write failure, but simultaneous writers and every power-loss situation are outside the guarantee. Handoff: Prateek will connect cleanup with error handling.

Prateek, 11:55-13:00. Explain the difference between an internal exception and the CLI's user-facing error contract. Both successful runs return zero and errors return two, although detailed help text and error wording can differ. Point to StoreOnceAction in python/main.py and parse_options in cpp/main.cpp for duplicate-flag checks. Open load_expenses and Tracker::load to show full row/header validation before add or delete can save. Explain why malformed stored data is an error rather than an empty tracker: silently replacing corruption would lose evidence and expenses. Relate this to the invalid-date demo and the tests that compare file bytes before and after failure. Handoff: Venkata will compare how the source is organized and built.

Slide 14: Performance: expectations and measurement limits (14:55-15:50)
Speaker: Venkata Sai Makani
- Measured here: correctness tests pass and the C++ build has no warnings
- No controlled benchmark establishes a runtime or memory winner
- Both read the entire CSV; mutations rewrite it and filtering scans records
- Expected tradeoffs: interpreter/dictionary overhead versus native values and copies
- Python groups with a dict then sorts; C++ updates an ordered map

Venkata, 14:55-15:50. Make the evidence boundary explicit: pass counts and warning-free compilation are observed; faster execution and smaller memory use were not measured in a controlled benchmark. Explain source-derived costs: both load all n rows and scan them for queries, and both rewrite n rows after a mutation. Python dictionary grouping is normally expected constant-time per update and sorts the k category keys for output; C++ map updates are logarithmic in k and iteration is sorted. Python dictionaries and interpreter-managed objects can add overhead, while C++ value copies in selection also have a cost. File I/O can dominate small datasets. Describe a fair future benchmark: identical generated datasets, commands, storage, optimized builds, repeated runs, and separate elapsed-time and peak-memory measurements. Handoff: both members will explain the verification evidence.

Slide 16: Limitations and lessons from the comparison (16:45-17:30)
Speaker: Prateek Sahay / Venkata Sai Makani
- Scope: single writer, USD, printable ASCII, bounded local CSV storage
- No concurrent writes, GUI, database, authentication, or benchmark results
- Shared validation and tests prevent subtle cross-language divergence
- Language choice should follow constraints: iteration speed, ownership, and deployment

Both members, 16:45-17:30: Prateek speaks for 20 seconds, Venkata for 25 seconds. Prateek: explain that the deliberate single-user scope keeps behavior deterministic; concurrency was considered as a course topic but adds no benefit to this CLI without proper writer coordination. Python offered compact standard-library tools for dates, CSV, and argument parsing. Venkata: explain that C++ required explicit calendar and CSV checks but made ownership and field types visible. A future multi-user version would need storage locking or a transactional database, and Unicode support would require a revised shared validation/search contract. The practical lesson is to define observable behavior first, then choose language idioms and verify their equivalence. Handoff: close together and invite questions.
